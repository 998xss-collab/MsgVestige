# 数据可见性矩阵 (R4)

> **这份文档回答一个问题**: 微信里的每一类数据, 我们**到底能不能拿到**, 以及**从哪条路拿**。
>
> **每一格都是真库跑出来的**, 不是照代码推断 —— 这是本文档唯一的价值所在。
> 证据库: 真加密源库 `X:\xwechat_files` 的 `wxid_ym85*******g22` 账号,
> 用 `msgvestige ingest --no-messages --all` 建了一个 1 GB 的 L1(254 秒), 逐表数了真实行数。
> 消息本体的行数另取自一个只采单会话的 11 GB 基准库(210 万条)。
>
> 生成日期: 2026-07-28 · 对应 commit: 见本文件的 git 历史

---

## 一、五种取法是什么

| 取法 | 是什么 | 拿数据的入口 |
|---|---|---|
| **① 落库** | `ingest` 把加密源库解密 + 转换, 落进自己的 L1 库 | `msgvestige ingest` |
| **② 冷查** | 查已经落好的 L1 库(快, 但可能不是最新) | `--mode cold` |
| **③ 热查** | 直读加密的微信库拿实时数据(慢, 但一定最新) | `--mode hot` |
| **④ 导出** | 把数据/媒体文件落到磁盘上 | `export` / `export-*` / `media-ingest` |
| **⑤ 接口** | 给程序和 AI 用的两套接口 | HTTP 40 个端点 / MCP 45 个工具 |

命令行共 **60** 个子命令。

## 三、需要说明的格子

### A. 为什么有 11 张表是空的

空表: `message_mention` `message_location` `message_call` `message_card` `message_forward_item`
`message_hongbao_claim` `chatroom_member_event` `group_pay_member` 以及三张运行时表
(`write_lease` `chat_refresh_state` `capture_targets`)。

**前八张全部是从消息正文里派生出来的** —— 而本次建库用的是 `--no-messages`(只导小表, 4 分钟;
带消息要几小时)。所以它们空**不代表拿不到**, 只代表这次没导消息。

要坐实这几格, 得跑一次带消息的完整 `ingest`。**本文档不拿"代码里有这张表"当证据**, 所以如实
标 ⚪ 而不是 ✅ —— 这正是这份矩阵存在的意义: 区分"应该能拿到"和"实测拿到了"。

后三张是运行时状态表(写租约 / 采集水位 / 采集白名单), 空是正常的。

### B. 朋友圈和收藏没有热查版

这两类走的不是消息库, 而是 `sns` / `favorite` 专库。热查目前只覆盖消息库那一族分片。
不是拿不到数据(落库和冷查都齐), 只是没有"直读实时"这条路。

### C. `moment_feed` 33 万 vs `moment` 1.3 万

`moment` 是动态本体(去重后), `moment_feed` 是原始时间线条目(含大量重复投递)。两者不是一回事,
别拿 33 万当"有 33 万条朋友圈"。

## 四、这份矩阵**没有**覆盖什么

写清楚边界, 免得被当成"全都验过了":

1. **只验了一个账号**(`wxid_ym85*******g22`)。多账号库、别人的装机路径没验。
2. **② 冷查 / ③ 热查 / ④ 导出 / ⑤ 接口 四列, 验的是"这条路存在且命令/工具/端点在册"**,
   不是每一格都真跑了一遍取数。逐格真跑需要 60 子命令 × 12 类的组合, 那是另一件事的量。
   ① 落库这一列是**逐表数出来的真实行数**, 证据最硬。
3. **消息本体的 210 万条来自另一个库**(只采了单个大群), 不是本次这个 1 GB 库里的数。
4. 空表那 8 张需要带消息重跑才能坐实(见说明 A)。

## 五、怎么重跑这份验证

```bash
# 建库(小表, 约 4 分钟; 别漏 --no-messages, 否则导消息要几小时)
msgvestige ingest --no-messages --all --l1-db <输出.db> --wxid <账号> --wechat-data-dir <微信目录>

# 逐表数行数
msgvestige exec --l1-db <输出.db> "SELECT name FROM sqlite_master WHERE type='table'"
```
